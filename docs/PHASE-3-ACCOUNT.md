# Customer accounts
Profile name/alias update requires current password. Mobile login identity cannot be changed until a verified mobile-change flow is available. Password change preserves the active session and invalidates other sessions. Verified recovery email is optional, unique, and requires current password plus a one-time expiring confirmation on the logged-in account. Password reset applies only to verified customer emails, uses Django's expiring password token with customer email binding, generic responses, rate limits, encrypted SMTP and fixed HTTPS origin. Manager accounts are excluded. SMTP defaults disabled; no mail is sent without configuration. Test uses local-memory mail, not live delivery. Owner-scoped order detail.
Deployment environment: ARAK_MAIL_ENABLED=1, ARAK_PUBLIC_ORIGIN=https://your-verified-domain, ARAK_SMTP_HOST, ARAK_SMTP_PORT, ARAK_SMTP_USER, ARAK_SMTP_PASSWORD, ARAK_FROM_EMAIL, ARAK_SMTP_TLS or ARAK_SMTP_SSL (exactly one). Supply secrets through protected environment, never Git. No actual provider selected or purchased. Live delivery and deliverability must be tested before release.
