# پشتیبان‌گیری روزانه اراک کالا
اسکریپت backup-daily.sh فقط روی میزبان مجاز و دارای Docker Compose اجرا می‌شود. کد ردیابی‌شده همان commit (بدون آرشیو مستقل sepas)، پایگاه داده، تصاویر و فهرست SHA256 را در پوشه خارج مخزن ذخیره می‌کند؛ برنامه فقط هنگام ثبت snapshot متوقف می‌شود و بازیابی در پوشه جداگانه آزمایش می‌شود. نسخه‌های قدیمی خودکار حذف نمی‌شوند. فایل .env واقعی، کلید خصوصی APK و اطلاعات محرمانه زیرساخت باید با روش مستقل، رمزگذاری‌شده و محدود نگهداری شوند. بدون آن‌ها بازیابی کامل عملیاتی تضمین نیست. فایل‌های ردیابی‌نشده به آرشیو سورس افزوده نمی‌شوند.

پس از تأیید مالک، روی میزبان مسیر واقعی پروژه را جایگزین کنید؛ پوشه خصوصی با chmod 700 تهیه کنید؛ یک بار با sudo bash deploy/backup-daily.sh /secure/arak-backups اجرا و خروجی را بررسی کنید. فایل‌های service و timer نمونه‌اند؛ نصب و فعال‌سازی systemctl enable --now arak-kala-backup.timer نیاز به دسترسی و مجوز میزبان دارد. ساعت ۳ بامداد محلی پیش‌فرض است. این زمان‌بندی اکنون نصب نشده است. برای پشتیبان خارج میزبان ابتدا مقصد اختصاصی و رمزگذاری مورد تأیید مالک را تعیین کنید؛ فایل حاوی اطلاعات مشتری است و خودکار به Google Drive یا سایر سرویس‌ها ارسال نمی‌شود. پس از انتقال رمزگذاری‌شده باید وجود، اندازه، checksum و امکان بازیابی نسخه خارج میزبان آزموده شود.
